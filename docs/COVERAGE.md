# Test coverage

Coverage includes application code, including frontend routes, providers and translation configuration, and backend storage adapters, messaging, seed, controllers and services. Dependencies, generated framework output and test support are not application code. No application file is excluded and there are no coverage-ignore annotations.

Verified on November 14, 2026: 110 frontend tests and 69 backend tests passed, with no skipped tests in the PostgreSQL-enabled run. Frontend statements, branches, functions and lines reached 100%; backend instructions, branches, methods, lines and classes reached 100%. Every configured per-file/per-class check passed.

## Frontend

From `frontend`, run:

```shell
npm run test:coverage
```

Vitest uses V8 coverage and requires 100% statements, branches, functions and lines **per file**. All `src/**/*.ts` and `src/**/*.tsx` files are included, excluding test files and `src/test` setup. Type-only modules have no runtime instructions to measure. The command fails if any measured file drops below a threshold.

Open `frontend/coverage/index.html` after the run. JSON, JSON summary, LCOV and terminal reports are also generated. Reports are ignored by version control.

## Backend

From `backend`, run:

```shell
./mvnw verify
```

On Windows use `./mvnw.cmd verify`. JaCoCo starts fresh on every test run, generates reports during `verify`, and requires 100% lines, branches, instructions and methods **per class**. The command fails on a coverage regression. The default suite uses isolated H2 databases; the PostgreSQL migration/seed test needs an explicit database configuration and is otherwise skipped.

To include real PostgreSQL safely, start Compose's PostgreSQL and run from the project root:

```powershell
./scripts/verify-backend-coverage.ps1
```

The script creates a new uniquely named database, runs Maven with the PostgreSQL test enabled, restores environment variables, and drops only that verification database in `finally`. It does not point tests at the application database. An optional `-MavenCommand` argument can select an installed Maven executable instead of the wrapper. The local `.env` supplies PostgreSQL credentials and port without printing passwords.

Open `backend/target/site/jacoco/index.html`. XML and CSV reports are generated beside it.

## GitHub Actions

The `CI` workflow in `.github/workflows/ci.yml` runs on every push and pull request, and can also be started manually. Its two independent jobs enforce the same coverage thresholds as local runs:

- **Frontend lint and 100% coverage** installs the lockfile with Node.js 24, checks formatting, ESLint and TypeScript, runs V8 coverage, then builds Next.js.
- **Backend tests and 100% coverage** uses Java 21 and a fresh PostgreSQL 18 service for the migration/seed test, runs `clean verify`, and enforces the JaCoCo checks. PostgreSQL credentials in the workflow apply only to this disposable service; no application secrets are needed.

Coverage HTML/LCOV/JSON and backend test results are available as workflow artifacts for 14 days, including reports generated by failing runs. To prevent merging a failing pull request, configure a GitHub branch rule that requires both job checks; the workflow itself does not configure branch protection.

## Tested behavior and limits

Tests assert product creation/editing, dirty-form protection, image validation/replacement/removal, status transitions, combined searches, sorting/pagination, report submission/polling/downloads, localized errors, navigation, themes and cache invalidation. Backend tests also cover database conflicts, outbox races, malformed messages, lost processing leases, storage failures, temporary-file cleanup, worksheet rollover, unsafe formula-like cell text and seed idempotency.

Real browser flows remain complementary to automated coverage. SDK and UI primitive boundaries use test doubles for controlled failures; integration tests exercise actual application HTTP endpoints, databases and generated XLSX workbooks. A 100% coverage score means all measured code paths executed under these tests; it is not proof that every possible input, concurrency schedule or external-service failure is correct.
